# Save/NAND pre-port rebased onto main — 2026-10-10

[PR #371](https://github.com/yashin-sh/WiiCompiled-Switch/pull/371) originally
predated the bounded temporary NANDCreate and NANDWrite bridges. The user
requested that this PR be repaired and completed on 2026-10-10. Merge current
main into its existing branch while keeping both source-owned bridges, live
argument guards, diagnostic files and their complete refusal contracts. Broad
synchronous traits for those two addresses are removed because compile-time
native traits take precedence over the bounded registry.

Retain the PR's additional synchronous read/close, write callback, create/delete,
directory and safe-open/close entry points. These are pre-ported against
WiiCompiled `a135beb201042b20f390c6695ca6b26768820fb4`; they have not all been
observed on Switch. Each newly enabled entry records a distinct `RMCP01_NAND_*`
stage. Existing ordinary opens continue to use the current SD-backed backend;
this work does not claim the upstream shadow protocol for every NANDOpen family.

Write returns the actual fwrite count, even if its subsequent fflush fails,
matching pinned NANDWrite. NANDWriteAsync delivers that count to the real queued
callback and maps a non-negative result to 0 in the caller's r3. Creating an
existing directory succeeds; creating a path occupied by a regular file returns
-6. File creation uses an exclusive open so a competing creator cannot truncate
an existing file.

Writable safe opens seed a sibling shadow. Safe close flushes and fsyncs the
stream, closes it, renames the shadow over the original, then attempts a parent
directory fsync as the pinned POSIX implementation does. Flush, file-fsync,
fclose and rename failures return -64; failures before rename preserve the
original and remove the failed shadow. Read-only safe handles remain distinct
from ordinary handles. Normal and safe closes publish flags 2 and 4 respectively;
a safe-close flag 5 follows the pinned flag-6 result. An active shadow is owned
under the handle mutex through close/commit: a second opener cannot discard it
as stale. A fclose error consumes the stream and cannot leave a dangling FILE
pointer in the handle map.

## Reproducible validation

`bash scripts/test-nand-save.sh` exercises actual native dispatch traits, the
production Memory slice, real owned FILE streams, the production callback queue
and isolated synthetic filesystem data in both rendered modes. ASan, fatal
UBSan and LeakSanitizer remain active. Pinned NANDWrite and NANDCreateDir bodies
are extracted from the verified dependency revision as result oracles. The
suite covers 54 native dispatches and 17 actual guest callbacks per mode,
including CPU preservation, binary tails, stale scratch replacement, read/write
safe handles, second-opener refusal, repeat close, real buffered /dev/full,
invalid spans and controlled flush/fsync/fclose/rename failures.

Existing NANDCreate contracts retain 14 admitted cases, 84 real abort refusals
and the exclusive-creation race per mode. NANDWrite retains 9 admitted cases
and 311 real abort refusals per mode; its storage-error fixture additionally
checks the strengthened ordinary-close fsync failure before verified cleanup.
The new save suite runs in the required gx-contracts CI job.

The complete exact-HEAD CI rollup and a separate fresh private rendered/Discovery
build must pass before this PR merges. Private build products, source hashes,
mutation results and raw logs remain excluded from the public repository.
