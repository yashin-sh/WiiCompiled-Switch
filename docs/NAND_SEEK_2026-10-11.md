# Bounded owned-handle NANDSeek rewind — 2026-10-11

The [fresh NANDMove trial](HARDWARE_NAND_MOVE_SEEK_2026-10-11.md) reaches
PAL NANDSeek `0x8019B964` with offset 0 and origin 0 before the first save-data
write chunk. Add a source-owned registry bridge which admits this rewind only
for a complete readable file-info object, a live owned ordinary stream,
open flag 1 and authoritative host mode 2. Safe shadow handles, stale/foreign
fds, other modes, incomplete spans and every different offset/origin are
refused through the existing durable unsupported-dispatch abort before any
seek/tell call. No fixed file-info address, fd or guessed filename grants
admission. Ordinary NANDOpen does not initialize the safe-open-specific access
byte; it is preserved and reported as opaque rather than used as a mode guard.

Perform the real fseek/ftell sequence under the handle mutex. Match pinned
WiiCompiled `a135beb201042b20f390c6695ca6b26768820fb4`: fseek failure returns
-64; after a successful seek, return ftell verbatim, including -1 on a failed
position query. Correct the existing shared seek backend's -1 normalization
so its asynchronous frontend also preserves that pinned result. Only r3
changes in the bridge; guest bytes and other CPU state are preserved.
Successful admission records `RMCP01_NAND_SEEK` and the actual owned-handle
metadata/result, while refusal records `NOT_CALLED`.

`bash scripts/test-nand-seek.sh` links the actual dispatcher/registry, production
Memory and owned-handle runtime, real streams/files and extracted byte-verified
pinned seek/origin bodies. Both modes keep ASan, fatal UBSan and LeakSanitizer
active. Each mode passes 14 admitted calls and 331 genuine abort refusals.
The suite checks real position changes from 7 to 0, unaligned and
complete end-boundary file-info objects, opaque-byte preservation, controlled
seek/tell failures, the shared backend's raw -1, stale fds, modes, safe shadow
exclusion even after a forged ordinary flag, every open flag and bitwise
argument variants. Refusals prove an actual abort, unchanged CPU/guest/file
snapshots, and no seek/tell call. This does not pre-port other seek tuples or
relax the retained temporary NANDWrite guard.

The new contract runs in required gx-contracts CI. Existing create/write/move,
save/callback and affected GX registry contracts are rerun. Semantic negative
controls, the exact-source private rendered/Discovery/SDK build and scoped
provider/retention audit, and every published check in the complete exact-HEAD
rollup must pass before merge/deployment. Corrected console execution remains
pending; this is not complete save/recovery acceptance.
