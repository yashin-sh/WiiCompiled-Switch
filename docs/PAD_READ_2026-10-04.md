# PADRead Switch input bridge — 2026-10-04

The [sphere console run](HARDWARE_RESULTS_2026-10-04_SPHERE_PAD_READ_FRONTIER.md)
returns from both sphere variants, then stops at PAL PADRead `0x801AF44C` with
four-channel status buffer `0x9025F0D0`. The pinned WiiCompiled HLE uses
Aurora/SDL controller objects. This bridge uses the existing Horizon input
service and its single configured default/handheld controller instead.

## Contract and scope

PADRead polls the existing libnx PadState once and encodes four 12-byte slots
with the **unchanged pinned PadStatusContract::Encode**. Channel 0 is connected
only when `padIsConnected` says so; channels 1..3 have error -1 and zero input.
Disconnected or uninitialized host input cannot leak stale buttons or axes.
The bridge returns rumble capability mask zero because no actuator backend is
implemented. It preserves the complete CPU context except the return in r3.

GC button masks come directly from the pinned Dolphin SDK (L=0x40, R=0x20).
Host expected packets assert these SDK constants independently. Buttons retain
their Nintendo labels: A/B/X/Y, directions, L/R, Plus as Start,
and either ZL or ZR as GC Z. Digital L/R also produce full analog trigger values
255, matching the pinned digital-trigger contract. Sticks use signed /256
scaling bounded to -127..127; libnx positive-up Y is preserved. The existing
translated PADClampCircle2 remains responsible for game-side stick clamping.
Analog A/B remain zero, as in the pinned ordinary controller path.

The full 48-byte guest range is checked before polling or writing. Null returns
zero without polling. Invalid or wrapped ranges return zero without partial
writes and record `invalid-range`; valid reads record `read-pass`, buffer and
channel-0 connection state. SD diagnostics are rewritten only on transitions.
The existing Plus debug-exit handling is retained; this slice does not establish
full game interaction, four-player input, Wiimote emulation or rumble support.

## Validation

The host contract executes the real CPU bridge, Memory slice and pinned
big-endian encoder. Only guest allocation and physical input acquisition are
seams. **65,563 cases pass** under ASan, fatal UBSan and LeakSanitizer with -O2
and warnings treated as errors. Expected packed bytes independently check all
four slots, button masks, padding, analog triggers, complete signed HID stick
range, endpoint/sign behavior, unexpected host values, disconnect/reconnect,
null and invalid pointers, both-side canaries and CPU preservation. Invalid
ranges must not poll or write.

The host suite is added to build-switch alongside the thirteen previous
contracts. The actual devkitA64 syntax gate explicitly includes PADRead and
the Horizon service, whose button masks are asserted against actual libnx SDK
constants. The synthetic probe retains the native bridge without executing a
fabricated input read at startup. Fast-track CI checks both retained symbols.

The actual AArch64 syntax gate passes, including the Horizon service and
libnx button assertions. Five compiled mutations (false connection, wrong A
mask, swapped L/R, partial-range validation and inverted Y) are rejected by the contract.
Original upstream patch bytes and all nine nanosecond mtimes are unchanged.

All fourteen local host suites, script/workflow lint and 450 local Markdown
links pass. The fast-track probe is explicitly retained by the linker, as
well as checked in the resulting ELF.

All-workflow, private rendered build and console return validation are pending
for this candidate. The latest accepted hardware frontier remains PADRead,
with user-confirmed black output then an error. Successful host input tests
cannot establish recognizable game pixels.
